\label{sec:method}

\textbf{Skills.} We evaluate A.L.F.R.E.D.\ on three personal-assistant skills: \texttt{caldav} (CalDAV calendar over a CLI bridge), \texttt{email} (Gmail via the \texttt{gws} CLI), and \texttt{telegram} (a Telethon-backed CLI). Each skill is documented in a \texttt{SKILL.md}~\cite{anthropic2025skills} file and distilled into a per-skill JSON pattern bundle (8 to 12 atomic patterns each). Composite patterns, each a fixed ordered sequence of atomic patterns, cover common multi-skill macros and are evaluated as a separate task category.

\textbf{Benchmark.} The 53-task suite is partitioned into nine categories: \emph{atomic\_easy} ($n{=}20$), \emph{v1\_collision\_regression} ($n{=}6$), \emph{v1\_activation\_regression} ($n{=}7$), \emph{v1\_blindspot\_regression} ($n{=}1$), \emph{composite\_easy} ($n{=}9$), \emph{real\_world} ($n{=}3$), \emph{needs\_skill\_keyword} ($n{=}2$), \emph{typo\_no\_recovery} ($n{=}1$), and \emph{off\_distribution} ($n{=}4$). The regression categories were constructed from named failure modes observed in pilot runs (\S\ref{sec:eval}); confusables and off-distribution items act as no-route negatives. Each task carries a natural-language prompt, a gold pattern identifier, and a gold-command regex that validates the emitted bash command.

\textbf{Model and infrastructure.} The Reflexer is Ministral-3-3B-Instruct~\cite{ministral2025} served locally via vLLM. We deliberately use the \emph{instruction-tuned} variant rather than a reasoning model: for a single-command generation task gated by a matched pattern, chain-of-thought adds latency without accuracy, and instruction-tuned small models have become the industry-standard backbone for structured tool emission. The Thinker is Qwen3.6-35B-A3B~\cite{qwen3_6}, a mixture-of-experts model (35B total, 3B active), run in a ReAct loop with full SKILL.md context. To make Thinker evaluation safe and repeatable, the bash tool is replaced by a \emph{dry stub} that returns per-skill synthetic JSON envelopes; the Reflexer track executes real commands against test sandboxes.

\textbf{Routing A/B harness.} We compare five router configurations: \texttt{baseline} (success-rate scoring only), \texttt{+laplace} (with $(s{+}1)/(n{+}2)$ smoothing), \texttt{+margin} (with margin-gated 2-way LLM disambiguation), \texttt{+position} (with the first-window position bonus), and \texttt{all\_combined}. Each variant is run on the full 53-task suite; the only changes between runs are router-config flags, while patterns, model, and prompts are identical.

\textbf{Metrics.} We report (i) \emph{routing accuracy}: fraction of tasks routed to the gold pattern; (ii) \emph{gold-command match}: fraction of executed commands matching the gold regex; (iii) \emph{Reflexer LLM latency} (real wall-clock from the served SLM); and (iv) \emph{Thinker total time} for the dry-stub baseline. Outcome-level success is not reported in this paper because backend availability dominates the signal at our scale; see \S\ref{sec:disc}.
